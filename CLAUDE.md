# CLAUDE.md

Project: studying the role of the embedding radius in LeJEPA. Source of truth for
design is the Technical Design / Research Outline notes in the research vault;
this file holds the rules every session must follow.

**Python:** 3.13

## Engineering Requirements

**Code style**
- Ruff and Pyright (strict). Google-style docstrings **and** imports.
- Never directly import classes or functions; import only modules
  (`import pathlib`, then `pathlib.Path`). `typing`, `typing_extensions`,
  `collections.abc` and `__future__` are exempt (as in the Google style guide).
  Enforced by `scripts/check_imports.py`.
- 88 characters per line.
- All of the above are enforced in pre-commit and runnable from the CLI with
  `make check` (`make format` to auto-fix).

**Testing**
- Every new feature comes with unit tests.
- Tests must be useful, not written to game coverage. Prefer testing the broader
  workflow to testing every local helper that is rightfully subject to change.
- If you find yourself modifying several tests (unless intended behavior is
  deliberately changing), fundamental behavior is probably being broken.
- CI must pass before any feature is merged to master.

**Research hygiene**
- Every new research question gets its own feature branch and its own name.
- All notes are markdown files under `research_notes/IDEA_NAME/`.
- If code was run to test a hypothesis, the exact command that was run **must** be
  included in the note (**CRITICAL**), with the branch name / version and the
  datetime in UTC at the top of the file. Each experiment gets its own file.

**Running code**
- All research code runs on the UChicago Data Science Institute cluster (SLURM).
  Instructions: https://cluster-policy.ds.uchicago.edu/. Access: `ssh fe.ds`.
- Data, checkpoints and the repo checkout live only in the locations configured in
  `.env` (see the variable table below). **Ask the user for permission before
  writing or deleting any directory outside those configured locations.** Never
  write real paths (local or cluster) into committed code or docs; they belong in
  `.env` only.

## Apps
- Every Python application ("script") lives in `apps/` at the top level. Apps are
  thin: parse a config, wire together library code from `src/lejepa_norm/`, write
  outputs. No reusable logic lives in an app.
- Keep the number of apps small (planned: `prepare_data`, `train`, `embed`,
  `analyze`). Add new behavior as a mode or config option of an existing app before
  considering a new app.
- Code in an app or research branch that turns out to be reusable is first
  abstracted into `src/lejepa_norm/` on its own feature branch (with tests), merged
  to master, and only then used by the research branch.

## Plotting
- Plotly only, exported to PNG with Kaleido. No HTML plot dumps.
- Kaleido >= 1.0 drives headless Chrome. Compute nodes may lack network access:
  install Chrome once from the login node (`kaleido.get_chrome()` /
  `plotly_get_chrome`) into a location under scratch and point Kaleido at it via
  `LEJEPA_NORM_KALEIDO_CHROME`.
- All plotting helpers live in `lejepa_norm.plotting` with one shared template
  (fonts, sizes, colors) so every figure looks the same.

## Experiment Notes (in addition to Research Hygiene)
- Result outputs are written into the experiment's markdown file as markdown
  tables generated by the analysis app, not hand-copied. Figures are PNGs saved next
  to the note and embedded with relative links.
- Every dataset and model backbone on Hugging Face is linked to its HF page. If the
  canonical source is not HF (e.g. STL-10's unlabeled split), link both the
  canonical source and the closest HF page, and say which one was actually used.
- Notes follow the template in the Technical Design (branch / commit, UTC datetime,
  commands, datasets, backbone; then Question, Setup, Results, Interpretation, Next
  steps).

## Architecture Documentation
- Module dependencies and data/experiment flow are Mermaid diagrams in
  `docs/architecture.md`. Update them in the same PR as any change that alters
  module dependencies or the flow between apps.

## Configuration & Logging
- Configs are typed dataclasses loaded from YAML in `configs/` (Pyright-checkable;
  no Hydra). Any field can be overridden from the CLI (`--set train.lr=1e-3`). The
  fully resolved config is saved next to every run's outputs.
- Logging is local only: per-step and per-epoch metrics are appended to
  `metrics.jsonl` in the run directory; plots are generated from it afterwards. No
  W&B or other networked tracking.
- Paths come from environment variables loaded from `.env` (git-ignored).
  `.env.example` with placeholder values (no real paths) is committed.

| Variable | Purpose |
|---|---|
| `LEJEPA_NORM_DATA_DIR` | Prepared datasets (STL-10, STL-10-C, DTD, SVHN) |
| `LEJEPA_NORM_RUNS_DIR` | Checkpoints, resolved configs, `metrics.jsonl` |
| `LEJEPA_NORM_EMBED_DIR` | Embedding dumps produced by `apps/embed.py` |
| `LEJEPA_NORM_NOTES_DIR` | `research_notes/` in the repo checkout |
| `LEJEPA_NORM_KALEIDO_CHROME` | Chrome binary used by Kaleido |
